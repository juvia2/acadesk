### 1-1. AI 영역 분담 (희망안)

| 담당 | 맡는 일 | 폴더 |
|---|---|---|
| lshee9008 · 에이전트 구축 | 상태 흐름(그래프, 상태 객체, 노드), 도구 허용 목록과 작업별 권한, RAG(문서 조각내기, 임베딩 저장, `academy_id` 필터 검색), Celery로 AI 작업 실행, 단계별 기록(`ai_runs`, `ai_steps`) | `ai/orchestrator/`, `ai/tools/`, `ai/rag/`, `workers/` 중 AI 작업 |
| Olivia · LLM·프롬프트 | 프롬프트 작성과 버전 관리, LLM·임베딩 모델 선정, 제공자 추상화(`llm.py`), 출력 형식(Pydantic 스키마), 결과 검증(금지어, 직접 쓴 숫자 검사), 평가 데이터셋과 품질 측정 | `ai/prompts/`, `ai/llm.py`, `ai/orchestrator/validators.py`, `tests/` 중 AI 평가 |

**두 영역이 만나는 지점 (회의에서 합의할 것)**

- 노드가 LLM을 부르는 함수 형태를 정합니다. 예: `llm.run(prompt_id, version, variables) -> 출력 스키마 객체`
  - lshee9008는 이 함수만 호출하고, 그 안의 프롬프트와 모델은 Olivia가 바꿉니다.
- 프롬프트 파일마다 입력 변수 목록과 출력 스키마를 같이 둡니다. 둘 중 하나가 바뀌면 상대방이 리뷰합니다.
- 검증 단계에서 실패하면 재시도할지, 사람에게 넘길지를 누가 정하는지 합의합니다. 제안: 검증 규칙은 Olivia, 재시도 흐름은 lshee9008.
- 평가 데이터셋(가상 안내 후보와 기대 결과)은 둘이 같이 씁니다. lshee9008는 흐름 전체를 테스트할 때, Olivia는 프롬프트를 개선할 때 씁니다.

**아직 담당자가 없는 영역 (회의에서 꼭 정할 것)**

첫 출시(MVP) 범위에는 AI가 없습니다. 그래서 아래 영역이 먼저 만들어져야 AI 작업도 실제 데이터 위에서 돌아갑니다.

| 규칙 엔진 | 안내 후보 생성, 보류·중단 조건 | |
| 승인함·발송 | 승인 API, 예약 발송, 발송 직전 재검증, 발송 대행사 연동 | |

- Olivia: 업무 모듈, 프론트엔드 (안내 문구가 화면에 어떻게 보이는지와 연결)
- 인프라: 처음 한 번은 lshee9008가 세팅

## 2. 첫 출시 범위 (MVP)

기획안의 출시 순서 2단계는 "수납 안내 + 당일 결석 확인, 담당자 승인함, 발송 이력"입니다. 이 범위에 동의하는지부터 정합니다.

| 안건 | 선택지 | 제안 | 결정 |
|---|---|---|---|
| MVP 기능 | 기획안 2단계 그대로 · 축소 · 확대 | 그대로. 반복 결석·과제·PDF·AI 문구는 MVP에서 제외 | |
| 데이터 입력 | CSV/엑셀 업로드 · 구글 시트 연동 · 직접 입력 화면 | CSV/엑셀 업로드만 (시트 연동은 확장 단계) | |
| 실제 발송 여부 | MVP부터 실제 문자 발송 · 발송 직전까지만(모의 발송) | 처음엔 모의 발송, 파일럿 직전에 실제 발송 연결 | |
| 파일럿 학원 | 있음 · 섭외 필요 | 섭외할 학원과 담당자를 정해야 함 | |
| 목표 일정 | | MVP 데모 날짜, 파일럿 시작 날짜 | |
| 다국어 안내 | MVP 포함 · 확장 단계 | MVP에는 보호자 `preferred_language` 필드만, 번역 발송은 확장 단계. 영어 먼저 | 영어 먼저 하기로 함 |
| 추가 기능 후보 | `docs/features.md` 맨 아래 "제안 기능" | 각 기능을 MVP / 확장 / 보류로 분류 | |
| 성공 기준 | 기획안 8장 검증 지표 중 선택 | 오발송 0건, 발송 전 차단 건수, 담당자 처리 시간 | |
